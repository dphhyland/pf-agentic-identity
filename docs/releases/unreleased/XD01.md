# Resource-server validation: libs/rs-validation, with a required replay store and a servlet filter

## Changelog

- Plan item X-D01: `services/demo-rs` moves to `libs/rs-validation` (`com.pingidentity.ps.oidf:rs-validation`), with
  the package `com.pingidentity.ps.oidf.rs` unchanged. `services/demo-rs` is now a relocation POM: a build that
  depends on `demo-rs` 0.5.0 or later resolves `rs-validation` at the same version.
- `DelegatedTokenValidator` is built with `DelegatedTokenValidator.builder(issuer, audience)`, and `build()` refuses
  without the authorisation server's keys and a `ReplayStore`. The replay store is asked last and refuses a DPoP
  proof it has seen (`invalid_dpop_proof`); a store that cannot answer is a 503. `RedisReplayStore` (`SET NX PX`
  through `platform.redis`) serves more than one node, `InMemoryReplayStore` one.
- The access token's `kid` must name exactly one published key (a token without one is refused, with no fallback
  to trying every key), its `typ` must be RFC 9068's `at+jwt` unless `accessTokenType(...)` says otherwise, and
  `nbf` is checked. The request method and URI are required.
- `act` is strict: a malformed chain, one deeper than 10 levels, and the legacy string form are refused; the string
  form only when this process runs under the development profile, through `allowLegacyStringAct()`.
- New: resource-server DPoP nonces (`DpopNonces`, an HMAC over a time window, with `use_dpop_nonce` and
  `DPoP-Nonce`), mTLS certificate-bound tokens (`cnf.x5t#S256`, under the Bearer scheme when `mtls(true)` is set),
  `RemoteJwks` (the JWKS through `platform.http`, cached by `kid`, refreshed on an unknown `kid` at most every 30 s,
  and its keys no longer used once twice the 10-minute maximum age old while fetches keep failing), and `ResourceServerFilter`, a `jakarta.servlet.Filter` that answers with the RFC 6750 and RFC 9449 challenges.
- Findings: U-0011 and U-0035 closed; F-0225, F-0226, F-0227, F-0228 and F-0229 recorded.

## Before you deploy

1. **Depend on `rs-validation`, not `demo-rs`.** The relocation resolves the old coordinates for you, with a Maven
   warning naming the new ones; change the dependency to `com.pingidentity.ps.oidf:rs-validation` to silence it.
   Nothing in this repository's image or release assets changes: neither module was staged or copied to `dist/`.
2. **Give the validator a replay store.** Replay protection is now required, so an embedding application must
   supply one: the constructors are gone, and `DelegatedTokenValidator.builder(issuer, audience).keys(...)
   .replayStore(...).build()` refuses to build without it. Use `RedisReplayStore` on a `RedisClient` from
   `platform.redis` when more than one node serves the resource, since every node must see the same store, and
   `InMemoryReplayStore` only for one node.
3. **Check the `typ` your access tokens carry.** The validator now requires RFC 9068's `at+jwt` (or
   `application/at+jwt`). PingFederate's JWT access token manager sends no `typ` unless its "Type Header Value"
   field is set; set it to `at+jwt`, as the conformance rig does, or build the validator with
   `accessTokenType(AccessTokenType.ABSENT)`. Tokens without a `kid` are refused too; PingFederate includes it
   unless "Include Key ID Header Parameter" was turned off.
4. **Stop sending `act` as a string.** A token whose `act` is a string holding JSON is refused in production. A
   development rig that still mints them can call `allowLegacyStringAct()`, which reads the process's own
   profile; `build()` then throws unless it is development (unset counts as production). `services/gm-api` still accepts the string form (F-0228).

## Notes

What changed. demo-rs was a two-class library whose caller had to replay-cache the proof's `jti` and never did
(U-0011). It is now `libs/rs-validation`: the same checks, stricter, plus the replay store, nonces, mTLS binding,
JWKS caching and a filter. The history follows the files: the move is its own commit. `DpopProofValidator` stays
in client-attestation, so rs-validation still depends on it; F-0225 asks plan item S8a to move it before
platform-pf's operator authenticator uses it.

What was checked, and how. Every refusal test an RFC requires quotes the sentence it enforces, read from the RFC
Editor's text of RFC 9449, RFC 8693, RFC 8705, RFC 6750, RFC 9068, RFC 7519 and RFC 7515 on 2026-09-28; the refusals
that are local policy (the exact and unshared `kid`, the `act` depth cap, no bearer mode, the 503s) say so instead.
The RFC 9449 section 4.3 and 11.1 quotes close U-0035: all twelve section 4.3 items are quoted on
`DelegatedTokenValidator.checkProof`, with the code that checks each. RFC 8705 and RFC 9068 have no `@Requirement`
prefix yet, so those quotes carry no id (F-0227). That PingFederate 13.1.3 omits `typ` by default and includes `kid` was read with javap from
`JwtBearerAccessTokenManagementPlugin` in the pinned image's `pf-core-plugins.jar` on 2026-09-28; no token was
minted from a booted PingFederate for this change. The relocation was checked by deploying both modules to a file
repository and resolving `demo-rs` from a consumer: Maven printed the relocation warning and the tree held
`rs-validation` and its dependencies. The whole reactor passed `mvn clean verify` on JDK 17.0.11 with Postgres and a
live Redis (`RedisReplayStoreLiveTest` among them), and rs-validation's 103 tests passed on JDK 20 and on the
pinned image's java 21.0.12.1 as well.

Residual risk. The Redis store is only as shared as the Redis: a resource served from several regions with
separate Redis instances accepts a proof once per region. `InMemoryReplayStore` behind a load balancer accepts a
proof once per node.
