# Health endpoints: live, ready, the detail and info, from components that register at start-up; every event counted

## Changelog

- Plan item O-4: PingFederate's runtime port answers `/agentic-identity/health/live` and
  `/agentic-identity/health/ready` (open, status only; ready is 503 when an enabled component is not ready or
  degraded), and `/agentic-identity/health` and `/agentic-identity/info` (the detail and the versions, only for the
  static admin bearer `OIDF_AUTHORITY_ADMIN_TOKEN`, 404 for anyone else). `libs/platform` gains `platform.health`
  (component parts, readiness, the documents), `libs/platform-pf` the `HealthServlet`.
- The servlets and filters register their parts under S-9's component names from their `init`, and record a
  failure's state and reason before rethrowing it unchanged; whether any of them starts is as before.
- Every event counts itself in `oidf_events_total{code,outcome}`, labels bounded by the event catalogues, with the
  gauges `oidf_events_dropped_fields` and `oidf_events_uncatalogued`. New in the register: F-0190 to F-0194.

## Before you deploy

None.

## Notes

Nothing to configure and nothing that starts differently. The four paths are new on the runtime port and collide
with nothing PingFederate 13.1.3's stock `pf-runtime.war` maps or this repository serves (`HealthPathsTest`, against
the stock web.xml's servlet mappings read from the pinned image on 2026-09-28). Live and ready need no credentials
and say only `{"status":"UP"}` or `{"status":"DOWN"}`. The detail and info answer a caller presenting the token the
federation operator API already takes, and 404 to everyone else, including every caller where no token is set;
S8b (Phase 3) moves them to the operator scope `oidf.health.read`. What ready means, and the cases where it is not
what an operator might expect - servlets that start on their first request (F-0193), a PingFederate named as its
own trust anchor before its keys are pinned (F-0192), an SSF setting that does not parse (F-0191) - are in
[docs/operator/health.md](../../operator/health.md).

The first event a copy of platform emits now registers that copy's metrics MXBean
(`com.pingidentity.ps.oidf:type=Metrics,copy=...`), which O-3 left unregistered until something counted: a JMX view
of the webapp's and, once an OGNL criterion emits, the engine's event counts.

gm-api.war keeps health of its own: once F-2 bundles platform-pf in it, it answers the same paths under `/gm-api`
from its own registry (libs/platform-pf's README, health). No build records the commit yet, so info's `commit` is
null (F-0190). F-0027, the observability umbrella, stays open.
