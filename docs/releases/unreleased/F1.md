# Two shared libraries: platform and platform-pf

## Changelog

- New modules `libs/platform` (`com.pingidentity.ps.oidf:platform`, JDK only) and `libs/platform-pf`
  (`com.pingidentity.ps.oidf:platform-pf`, PingFederate's jars provided), the shared base Phase 2 builds on
  (plan item F-1). They hold, so far: a per-classloader registry of what to close at shutdown, a component
  registry in S-9's seven states, a copy of rar-model's JDK-only JSON reader and writer, a logger that writes
  through commons-logging where the loader has it, and the guard an OGNL criterion runs behind.
- `oidf-jose` depends on `platform` and `pf-integration` on `platform-pf`, so `oidf.war` carries both jars and
  `stage-modules.sh` stages both, in both profiles, into the war and onto the engine's classpath. The
  `MANIFEST` is now the one list of staged jars: the image README, the Dockerfile, the SSF and `oidf-war`
  READMEs and the showcase point at it instead of counting.
- [docs/development/classloaders.md](../../development/classloaders.md) writes down the classloader rules the
  libraries follow.

## Before you deploy

1. **Deploy `platform-<version>.jar` and `platform-pf-<version>.jar` wherever you deploy `oidf-jose` and
   `pf-integration` today.** A consumer that builds its image from this repository's
   `build/pingfederate/Dockerfile` and `stage-modules.sh` gets them with nothing to do. A consumer that copies
   jars itself - pf-oidf-modules stages them, idp-agentic-demo commits built artefacts - must put both jars in
   both places PingFederate loads the modules from: the `pf-runtime.war` merge (`WEB-INF/lib`) and
   `server/default/deploy`, the engine's classpath where the OGNL criteria run. What fails without them: in this
   package, nothing yet - no class in any staged jar, plugin or war refers to platform (checked 2026-09-28 by
   searching every class file this build ships), so a missing jar is silent. From the first Phase 2 package that
   calls platform from a staged module, the class that calls it fails at first use with
   `NoClassDefFoundError: com/pingidentity/ps/oidf/platform/...`: a filter or load-on-startup servlet at
   deploy, an OGNL criterion on the first token request that evaluates it. Compare your deployed jars with the
   release's `MANIFEST`, which names every one.

## Notes

The two modules are the base the rest of Phase 2 builds on; this package adds only what the others need first.

- `platform.lifecycle.Lifecycle`: `register(name, resource)` and a `shutdown` that closes in reverse order,
  once, logging a failed close and closing the rest, within a budget (ten seconds by default) - each close on a
  short-lived daemon thread, so a hung one cannot hold up an undeploy; after a timeout the remaining closes start
  while the hung one is still running, so reverse order is kept only while closes finish in time. Whether a copy
  is the webapp's is `UNKNOWN` until F-2's listener marks it. The closer threads are the one `new Thread(`
  outside the future `platform.exec` ([F-0131](../../findings/F-0131.yaml)).
- `platform.component`: `Components.register(name, enabled)` and a handle per component, S-9's states with an
  operator-readable reason, and a snapshot for health. No supervisor or backoff (S9a, Phase 3).
- `platform.json.Json`: rar-model's reader and writer copied with its tests; rar-model is unchanged, and the
  duplication is [F-0130](../../findings/F-0130.yaml).
- `platform.log.PlatformLog`: commons-logging when the loader can see it - every PingFederate loader can, and
  PingFederate 13.1.3 routes it through `log4j-jcl` to server.log at the line's level - otherwise
  `System.Logger`, so the jar loads with the JDK alone. Not `java.util.logging` inside PingFederate, which
  13.1.3 logs as `ERROR [SystemErr]` ([F-0075](../../findings/F-0075.yaml)).
- `platform.pf.ognl.CriterionGuard`: runs a criterion's body and answers `false`, logged, for anything it
  throws, an `Error` included. Nothing calls it yet.
- Each module's pom and README carry one anchor comment per future owner, so the Phase 2 packages that fill
  them in parallel edit separate lines.
