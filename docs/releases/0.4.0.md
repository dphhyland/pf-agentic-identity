# 0.4.0 - Phase 1: the blockers closed or mitigated, the guard rails up

In progress: 0.4.0 is the version the poms have carried since 2026-09-27, and this page is written as its
pull requests land. Phase 1 of the production programme closes the 2026-09-26 review's first three blockers,
mitigates two more, seeds the findings register, and puts the CI and documentation guard rails in place.
Nothing here is released until David tags it; [CHANGELOG.md](../../CHANGELOG.md) carries the one-line
entries meanwhile.

**Read "Before you deploy" first** once it has anything in it.

## Before you deploy

Nothing yet. Every pull request that changes what a consumer must do - a setting that becomes strict, a
default that changes, a route that goes - adds its item here as it merges, naming its commit or pull request,
so this list is never assembled from memory at the end.

## Findings closed in 0.4.0

The findings register ([docs/findings](../findings/README.md)) is the record: one file per finding, each with
the pull requests that closed it and dated verification text. The findings this release is expected to close
are the ones targeted at it:

```sh
python3 tools/findings.py list --status closed          # closed, with the release that closed each in its file
python3 tools/findings.py --gate 0.4.0                  # what still stands in the way of this release
```

The register itself is new in 0.4.0 (plan item D-2), seeded from the review, the reviewer reports, the
plan's "Found while designing" list, and the assumptions `docs/unverified.md` had been carrying (now `U-`
entries, cross-referenced from that file).
